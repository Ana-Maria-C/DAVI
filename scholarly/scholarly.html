1. Abstract

DAVI (Data Visualization & Interaction) is a modular Single Page Application (SPA) designed to transform static movie datasets into an interactive Knowledge Graph. By leveraging the Semantic Web stack (RDF, SPARQL, Ontologies), DAVI moves beyond traditional relational database limitations, allowing users to explore movies through their hidden connections—shared genres, common tags, and implicit relationships.

The system implements a microservices architecture using FastAPI as an API Gateway and Apache Jena Fuseki as the triple store. The frontend, built with Angular 21, features advanced visualizations including a 3D Force-Directed Graph and interactive charts, providing users with a "big picture" view of the MovieLens 100k dataset.

2. Project Motivation

In the modern digital landscape, recommender systems are often "black boxes." Users are fed suggestions without understanding why. DAVI aims to democratize this data by:

  • Visual Transparency: Users can literally "see" the connections between a movie they like and its neighbors in the graph.
  • Semantic Reasoning: Instead of simple text matching, the system understands that "Rom-Com" is a sub-category of "Comedy," enabling smarter filtering.
  • Educational Value: Demonstrating how Linked Data principles can be applied to real-world entertainment datasets.

3. Technical Architecture

3.1 Microservices Design

The project adheres to a clean Service-Oriented Architecture (SOA). Each layer has a distinct responsibility, ensuring modularity and facilitating independent testing.

3.2 Technology Stack

We selected a modern, robust stack to ensure high performance and developer ergonomics:

Frontend (Client)

  • Framework: Angular 21 (Latest) - for component-based logic.
  • Visualization:
    • 3d-force-graph: WebGL-powered graph rendering.
    • ngx-charts: For statistical bar/pie charts.
  • UI Library: Angular Material - ensuring a consistent, accessible design.
  • State Management: RxJS - handling asynchronous data streams (filters, search results).

Backend (Server)

  • Framework: FastAPI (Python 3.9+) - High-performance, async I/O.
  • Validation: Pydantic - Data validation and settings management.
  • RDF Tools:
    • SPARQLWrapper: For executing queries against Fuseki.
    • rdflib: For parsing and serializing Turtle (`.ttl`) files.

Data Persistence

  • Triple Store: Apache Jena Fuseki.
  • Format: RDF/Turtle.
  • Containerization: Docker & Docker Compose.

3.3 System Architecture and API Structure

The backend exposes a RESTful API that abstracts the complexity of SPARQL. It transforms frontend JSON requests into SPARQL queries, executes them, and formats the results back to JSON.

Key API Controllers:

  • MoviesController (`/movies`):
    • GET /search: The core search engine. Accepts `genre`, `year_min`, `year_max`, `rating_min`. Constructs dynamic SPARQL queries using `FILTER` clauses.
    • GET /graph: Optimized for the 3D visualizer. Returns a distinct set of `nodes` (Movies, Groups) and `links` (Relationships).
    • POST /compare: Accepts a list of Movie IDs and returns their intersection (common attributes).
  • AnalysisController (`/analysis`):
    • GET /trends: Aggregates data to show "Most Popular Genres" or "Rating Distributions" using SPARQL `GROUP BY`.

4. Knowledge Model & Semantics

Unlike a SQL schema, our data model is a flexible graph defined by an Ontology. We used Protégé to design the schema and schema.ttl to persist it.

4.1 RDF Class Structure

The ontology defines the following core classes and properties:

  • :Movie (owl:Class)
    • Mapped to schema:Movie.
    • Properties: :movieId (integer), schema:name (string), :year (gYear), :hasGenre (ObjectProperty), :hasTagLabel (DatatypeProperty).
  • :Genre (owl:Class)
    • Instances include `:Action`, `:Comedy`, etc.
    • Hierarchical property: :subCategoryOf allowing inference (e.g., :War -> :Action).
  • :Rating (owl:Class - Reified Association)
    • Since RDF links are binary, we use a Rating node to connect a User and a Movie with a value.
    • Properties: :ratedBy, :ratingOf, :ratingValue (float).

4.3 Linked Data Principles

DAVI respects the 5-star Linked Data principles:

  1. OL: Data is available on the web (Open License).
  2. RE: Data is machine-readable (RDF/Turtle).
  3. OF: Non-proprietary format (CSV -> converted to TTL).
  4. URI: All entities have URIs (e.g., http://example.org/movielens/Movie/1).
  5. LD: (Planned) Links to extensive context via DBpedia.

5. External Data & SPARQL

The system transforms the raw MovieLens 100k dataset (CSV) into a semantic graph. The transformation logic (`convert_csv_to_rdf.py`) cleans the data, handles missing values, and mints URIs.

5.1 Advanced SPARQL Queries

We implement non-trivial queries to extract insights. For example, to find "Top Rated Action Movies from the 90s": 


PREFIX : <http://example.org/movielens/>
PREFIX schema: <http://schema.org/>

SELECT ?title ?avgRating
WHERE {
  ?m a :Movie ;
     schema:name ?title ;
     :hasGenre ?g ;
     :year ?year .
  
  ?g rdfs:label "Action" .
  
  # Aggregated Requests
  {
    SELECT ?m (AVG(?val) as ?avgRating)
    WHERE { ?r :ratingOf ?m ; :ratingValue ?val . }
    GROUP BY ?m
  }
  
  FILTER (?year >= 1990 && ?year < 2000)
  FILTER (?avgRating > 4.0)
}
ORDER BY DESC(?avgRating)
LIMIT 10

6. User Guide & Case Studies

6.1 Use Case: Exploring Relationships via 3D Graph

Scenario: A user wants to find "clusters" of related movies visually rather than scrolling a list.

Steps:

  1. User navigates to the "Graph View" tab.
  2. The system renders 50+ movies as nodes.
    • Blue Nodes = Movies.
    • Green Nodes = Genres.
  3. User drags a node; the physics engine (Force Atlas 2) dynamically rearranges the graph.
  4. User hovers over a "Star Wars" node. The graph highlights the "Action" and "Sci-Fi" genre nodes connected to it.
  5. User clicks the node to open the Movie Details modal.

6.2 Use Case: Semantic Search & Filtering

Scenario: A user looks for highly-rated movies from a specific era.

Steps:

  1. User goes to "Movie Library".
  2. In the sidebar, User selects:
    • Genre: "Thriller"
    • Year Range: 1995 - 2000
    • Rating: 4 stars+
  3. The list automatically refreshes. The backend injects these values into a SPARQL FILTER clause.
  4. The result shows movies like "Se7en" and "The Usual Suspects."

6.3 Use Case: Detailed Movie Analysis

Scenario: Assessing if a movie is worth watching.

Features:

  • Tag Cloud: Displays the most common words users associated with the film (e.g., "Atmospheric", "Twist Ending").
  • Rating Distribution: A visual breakdown showing if the movie is universally loved or polarizing.

6.4 Use Case: Comparing Movies

Scenario: A user can't decide between two movies.

Steps:

  1. In the Movie List, user clicks "+ Compare" on "Toy Story".
  2. User clicks "+ Compare" on "Aladdin".
  3. User clicks the floating "Compare (2)" button.
  4. A modal appears showing a side-by-side comparison:
    • Common Genres: "Animation", "Children".
    • Rating Delta: Toy Story (4.2) vs Aladdin (3.8).
    • Review Count: Which one is more popular?

6.5 Use Case: Visualizing Trends

Scenario: Analyzing the popularity of genres over time.

Steps:

  1. User navigates to the "Trends" page.
  2. A Bar Chart displays "Top Genres by Movie Count".
  3. A Pie Chart displays "Distribution of Ratings".
  4. These charts are powered by ngx-charts and fed by the `/analysis/stats` endpoint.

7. Future Development Roadmap

While the current iteration meets the core WADe requirements, we envision several enhancements for Version 2.0:

Phase 1: Enhanced Intelligence

  • Collaborative Filtering: Implement Matrix Factorization (ALS) to suggest movies based on user similarity, not just metadata.
  • Federated Queries: Execute live SPARQL queries against DBpedia to fetch the latest director info and actor biographies.

Phase 2: Social Features

  • User Accounts: Fully implement JWT authentication.
  • Watchlists: Allow users to save custom lists to the Knowledge Graph.
